# Как устроен инструмент «Цвета макетов»

Документ для того, чтобы через месяц вспомнить, что где лежит, и чтобы любой
разработчик мог подхватить. Пользовательская инструкция — в `README.md`.

## Из чего собран

Пять файлов, каждый делает ровно одно дело:

| Файл | Чем занят |
|---|---|
| `scan.py` | ходит в Figma и собирает сырые данные по одному файлу |
| `aggregate.py` | склеивает всё собранное в единый набор данных |
| `app.py` | локальный сервер: отдаёт страницу и API, запускает обходы |
| `app.html` | интерфейс: вкладки, таблицы, фильтры |
| `report.py` | делает из данных самодостаточный HTML для пересылки |

Зависимостей нет — только `python3`, который уже есть в macOS, и `curl`.
Ничего ставить не нужно.

## Откуда берутся данные

Figma REST API, только GET-запросы. Токен берётся из `FIGMA_TOKEN`, `token.txt` рядом с инструментом
или `~/.config/figma-colors/token` — в код он не попадает. В макеты не пишется ничего.

Используются два метода:

* `GET /v1/files/{key}?depth=1` — оглавление файла: список страниц с именами.
  Лёгкий запрос, содержимое не тянет.
* `GET /v1/files/{key}/nodes?ids=...` — содержимое конкретных узлов целиком.

## Как обходится файл

1. **Берём оглавление** и оставляем только страницы, чьё имя начинается на
   `Stage`. Архивные отбрасываем всегда по имени
   (`Arhive`, `Archive`, `архив`). Остальные страницы даже не скачиваются:
   это экономит около 60 % трафика.
2. **Каждую страницу режем на куски.** Сначала спрашиваем список её прямых детей
   (`depth=1`), потом качаем их группами по десять. Целиком страницу на полмиллиона
   слоёв Figma не отдаёт, а кусками — отдаёт.
3. **Если кусок всё равно великоват** (больше 210 МБ) — делим группу пополам и
   пробуем снова. Если не лезет даже один узел, спускаемся на уровень ниже и
   качаем уже его детей. Рекурсия ограничена пятью уровнями, дальше ошибка
   записывается в отчёт, а обход продолжается.
4. **Ответ разбираем и выбрасываем.** Распакованный JSON страницы весит сотни
   мегабайт; он живёт ровно столько, сколько нужно, чтобы пройти по слоям, и
   сразу удаляется. Поэтому обход 4,2 млн слоёв не упирается в память.

При сетевых сбоях запрос повторяется до семи раз: на `429` (слишком часто) ждём
30 секунд и дальше по нарастающей, на пятисотых — 15 секунд.

## Что считается при обходе

Идём по каждому слою и смотрим два списка красок: `fills` и `strokes`.
Невидимые краски (выключен глаз) пропускаем.

* **Сплошная краска** — записываем цвет. Прозрачность берём как
  `color.a × opacity`: в Figma для сплошной заливки ползунок непрозрачности
  пишется именно в `opacity`, так что это и есть то число, которое человек
  выставил в пипетке.
* **Градиент** — записываем каждый цвет-стоп отдельно и, кроме того, запоминаем
  весь рецепт целиком (`#A→#B→#C`), его вид (linear, radial, angular, diamond)
  и примеры слоёв. **У стопа берётся только его собственная прозрачность**,
  прозрачность всего слоя в неё не складывается. Иначе один и тот же градиент,
  положенный на 75 % и на 50 %, плодил бы два разных набора цветов.
* **Привязка.** Заодно смотрим, стоит ли за краской переменная (`boundVariables`)
  или стиль (`styles`). Если нет — применение считается «набрано руками».
* **Примеры слоёв.** На каждый цвет внутри каждой страницы запоминаем до
  20 слоёв: id, имя, тип и в какой список попал (заливка или обводка).

## Что и где хранится

```
инструмент-цвета/
├── sources.json          список источников: что обходим
├── out/                  результаты обхода — главное хранилище, 21 МБ
│   ├── КЛЮЧ.json             обход всего файла
│   └── КЛЮЧ__ID.json         обход одной страницы
├── raw/                  временные ответы Figma, чистится на ходу
├── цвета-макетов.html    выгруженный отчёт для пересылки
└── allfiles.json         список 35 файлов папки 2.1 для первого запуска
```

Один файл в `out/` — это один срез. Внутри:

```json
{
  "file": "<имя файла>", "key": "<ключ файла>", "nodes": 21319,
  "skipped": ["Cover", "Local components", "Arhive"],
  "errors": [],
  "pages": [{
    "id": "1:3", "name": "Stage 1", "nodes": 19152,
    "colors": {
      "#252525": { "flat": 16, "grad": 0, "raw": 0,
                   "ex": [["4038:5000", "<имя слоя>", "SECTION", "fill"], …] }
    },
    "grads": {
      "#FFFFFF→#FFFFFF@0%": { "n": 82, "type": "GRADIENT_LINEAR", "ex": [...] }
    }
  }]
}
```

Это обычный JSON, его можно открыть и прочитать глазами.

### Почему срезы лежат отдельно

Один и тот же файл можно обойти целиком и отдельно по странице. Чтобы эти два
обхода не затирали друг друга, они пишутся в разные файлы: `КЛЮЧ.json` и
`КЛЮЧ__ID.json`. При сборке каждая страница берётся **ровно один раз — из самого
свежего среза** (сравниваются даты файлов). Поэтому цифры не удваиваются, а
повторный обход страницы просто обновляет её данные.

### Когда данные пересобираются

* Обход **по ссылке, нажатой руками** — всегда заново, кэш не подставляется.
* Обход **всех файлов** без ссылок — пропускает уже собранные. Это нужно, чтобы
  прерванный проход можно было продолжить с того места, где он встал.

## Как данные превращаются в цифры

`aggregate.py` читает все срезы и строит единый набор:

1. **Выбирает свежие срезы** — по одному на страницу.
2. **Складывает цвета** по всем страницам: применения в заливках, применения в
   градиентах, сколько набрано руками, в скольких файлах встречается, и список
   страниц с примерами слоёв.
3. **Определяет группу цвета.** Переводит hex в HSL и раскладывает по правилу:
   насыщенность не больше 0,08 — ахроматика (светлее 0,93 → White, темнее 0,12 →
   Black, остальное Neutral); дальше по тону — Red до 14°, Orange до 42°, Yellow
   до 70°, Green до 157°, Teal до 196°, Blue до 248°, Purple до 288°,
   Magenta до 330°, выше — снова Red.
4. **Сверяет с китом.** Читает `tokens.json` рядом с инструментом (или CSV, путь к нему в `settings.json`) и помечает
   цвета, чьё значение в точности совпадает со значением токена. Заодно считает,
   какие токены не встречаются в макетах ни разу.
5. **Режет хвосты.** На цвет показывается до 10 страниц, в каждой до 20 слоёв.
   Без этого у частых цветов были бы десятки тысяч ссылок и страница не открылась бы.

На выходе — один объект: файлы, страницы, цвета, градиенты, токены, источники и сводка.

## Как работает приложение

`app.py` поднимает сервер на `127.0.0.1:8800` — только на этой машине, снаружи не
виден. Отдаёт `app.html` и восемь методов:

| Метод | Что делает |
|---|---|
| `GET /api/state` | список источников со статусом и прогресс текущего обхода |
| `GET /api/data` | весь набор данных (около 6 МБ) |
| `GET /api/job` | состояние обхода |
| `POST /api/add` | добавить источник по ссылке |
| `POST /api/remove` | убрать источник из списка |
| `POST /api/refresh` | запустить обход: один источник или все |
| `POST /api/stop` | остановить обход |
| `POST /api/export` | собрать отчёт для пересылки |

Обход идёт в отдельном потоке и запускает `scan.py` как подпроцесс — по одному
источнику за раз, последовательно. Прогресс пишется в общую структуру под
блокировкой, страница опрашивает его раз в 2,5 секунды и рисует полосу и лог.
Когда обход заканчивается, страница сама перечитывает данные.

Два обхода одновременно запустить нельзя: второй запрос получит отказ.

## Ссылки на слои

Ссылка вида `https://www.figma.com/design/{ключ}?node-id={id}` открывает файл и
выделяет слой.

Загвоздка в инстансах: слой внутри инстанса имеет составной id вроде
`I4041:9063;3233:43784;777:40`, и по такой ссылке Figma открывается ненадёжно.
Поэтому для них ссылка ведёт на **сам инстанс** (первый сегмент пути) и помечена
значком `↗`. Заодно такие ссылки схлопываются: если двадцать найденных слоёв
лежат в трёх инстансах, показываются три ссылки, а не двадцать одинаковых.

## Отчёт для пересылки

`report.py` берёт тот же `app.html`, подставляет данные вместо заглушки
`/*__DATA__*/ null` и сохраняет как `цвета-макетов.html`. Страница видит, что
данные вшиты, убирает вкладку «Источники» и работает без сервера и без
интернета. Интерфейс один на оба режима — чинить нужно в одном месте.

## Пределы и известные ограничения

* **Тёмные значения тем не видны.** Обход читает цвет таким, как он отрисован в
  текущей теме страницы. Если макет нарисован в светлой теме, тёмное значение
  темозависимого токена в данные не попадёт.
* **Цвета эффектов не считаются.** Тени и свечения живут в `effects`, а разбираются
  только `fills` и `strokes`.
* **Изображения и видео** как заливки пропускаются — у них нет цвета.
* **Счётчик слоёв приблизителен.** При разбиении страницы на куски родительские
  узлы попадают в несколько ответов, поэтому число «слоёв просмотрено» на пару
  процентов завышено. На подсчёт цветов это не влияет: краски лежат на самих слоях.
* **Полный обход — около получаса** на 32 файла и 4,2 млн слоёв в шесть потоков.
  Через приложение обход идёт в один поток и занимает дольше; для полной
  пересборки быстрее запустить `scan.py` вручную несколькими процессами.

## Если что-то пошло не так

* **«Нет токена Figma»** — создать токен в Figma (Settings → Security → Personal
  access tokens) и положить строку в `token.txt` рядом с инструментом.
* **«СБОЙ В ССЫЛКЕ: в файле X нет узла Y»** — в ссылке неверный `node-id`.
  Ничего не сохранилось, можно просто дать правильную ссылку.
* **Обход встал** — нажать «Остановить», потом «Обновить». Уже собранные файлы
  не потеряются, проход продолжится.
* **Хочется начать с нуля** — удалить содержимое `out/` и запустить «Обновить все файлы».
