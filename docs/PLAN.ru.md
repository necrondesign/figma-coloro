# coloro v2 — план переработки

coloro становится единым инструментом: учёт цветов, поиск по макетам и общая картина
«что хорошо, что плохо». Объединяет учёт цветов и поиск по макетам в один продукт и закрывает то,
что нашли три волны ревью.

## Для кого и зачем

Дизайнер открывает инструмент с одной из задач и всегда уходит со ссылкой на конкретный слой:

- **Левые цвета** — цвета мимо дизайн-системы, редкие, «почти токен» → где они → открыть в Figma.
  Дизайн-система — справочник токенов, который человек загружает сам (CSV или JSON), любой
- **Найти текст** — слово или фраза → где → открыть
- **Найти размер** — W × H с допуском → где → открыть
- **Найти компонент** — со всеми вариантами, в том числе внутри инстансов → где → открыть

Главный экран — общая картина: сводка с изменением с прошлого обновления и карта
«файлы × проблемы», где цвет ячейки говорит, насколько плохо.

## Принципы

- **Универсальный продукт.** Ни одного решения, привязанного к конкретной команде или макетам.
  Названия страниц, секций, правила учёта — всё задаётся фильтрами, а не кодом.
- **Хранится всё, решается при просмотре.** Загрузка ничего не отбрасывает и ничего не решает:
  скрытые слои, архивные страницы, служебные секции — всё ложится в базу с метками.
  Что учитывать, выбирает человек фильтрами, и меняется это без перезагрузки макетов.
- **Фильтры, а не настройки.** Скрытые слои, архивные страницы, секции по названию, страницы
  по названию, дата изменения файла, дата загрузки, дата появления находки. У каждого фильтра есть
  состояние по умолчанию — оно видно чипом на экране и переключается одним кликом.
  Набор фильтров можно сохранить и выбрать по имени.
- **Без установки.** Только стандартный Python. SQLite встроен, база — один файл.
- **Ничего не теряется.** Каждая страница записывается сразу, как скачалась. Сбой одной страницы
  не трогает остальные; следующее обновление докачивает только недостающее.
- **Обновляется только изменившееся.** Версия файла проверяется лёгким запросом до загрузки.
- **Двойной счёт невозможен по устройству.** Данные хранятся по (файл, страница), а не по ссылке.
- **Что загружать — можно ограничить, но не обязательно.** Для огромных файлов у источника можно
  указать, какие страницы брать. По умолчанию — все.

## Состояния фильтров по умолчанию

Выбраны по одному правилу: **считать то, что видно на экране.**

| Фильтр | По умолчанию | Почему |
|---|---|---|
| Скрытые слои | не учитывать | Не рисуются. На проверенных макетах 97% скрытых — выключенные слои внутри компонентов |
| Архивные страницы | не учитывать | Архив — это прошлое, а не текущее состояние. Распознаются по названию: archive, архив, arhive и написание с кириллической «с» |
| Секции по названию | ничего не исключено | Человек сам добавляет названия служебных секций |
| Страницы по названию | все страницы | |
| Дата | за всё время | |

## Этапы

1. **Фундамент** — загрузка, база, правила, тесты на правила, сверка с реальными данными.
2. **Цвета и общая картина** — инвентарь на SQL, левые цвета с ближайшим токеном, главный экран, история.
3. **Поиск** — текст, размер, компонент, цвет; ссылки на слой с запасным https-адресом.
4. **Интерфейс** — общий слой стилей и скриптов, оформление в духе Booster, светлая и тёмная темы.
